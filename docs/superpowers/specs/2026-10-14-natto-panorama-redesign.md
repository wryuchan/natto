# 納豆調理ゲーム「調理台パノラマ」再設計仕様

- 日付: 2026-10-14
- 状態: Claudeレビュー反映済み・ユーザー承認済み（2026-10-15）
- 対象リポジトリ: `git@github.com:wryuchan/natto.git`
- 公開URL: `https://wataryuu.com/natto/`
- 関連仕様: `docs/superpowers/specs/2026-10-12-natto-game-design.md`

## 1. 目的

現在のゲームを、画面外の工程ボタンで3つの独立シーンを切り替える構成から、一つの3D調理台を自分で見渡して調理するゲームへ作り直す。

プレイヤーは、まな板、鉢、お茶碗を3D空間内で選び、包丁、箸、鉢を直接操作する。参考ゲームに近い「自分で道具を持って調理する感覚」を中心にしつつ、粘る納豆の細かな移送だけは短い自動アニメーションにして、Android Chromeでも安定して遊べるようにする。

本仕様は、既存仕様の画面構成、ステーション構成、入力設計、初期GameState、3D表示、モバイル受け入れ条件を置き換える。採点、20種類の称号、保存、日本語・英語、効果音、アクセシビリティ（既存仕様§17）の基本方針は、変更点を明記した箇所以外は既存仕様を維持する。

本仕様は二段階で公開する（§12）。Phase 0で現行構成のまま緊急不具合を直して公開し、Phase 1で調理台パノラマへ移行する。

## 2. 解決する問題

| # | 問題 | 原因 | 対応Phase |
|---|---|---|---|
| P1 | Android Chromeの縦画面でCanvasが縮み、操作できない | `.app-shell`が`height: 100svh`のgridで、Canvas行が`minmax(0,1fr)`。34rem以下で`min-height: 0`になり、下に積んだ5行の操作UIに高さを奪われる（360×640で182px、URLバー表示中はさらに縮む） | 0（CSS修正）、1（全画面Canvas） |
| P2 | 納豆が鉢に入っていないのに混ぜ画面の鉢が茶色い | 鉢の内容物表示が状態と連動していない | 0 |
| P3 | 盛り付け画面の鉢とお茶碗が器に見えない | 開いた`CylinderGeometry`、画角、配置 | 0 |
| P4 | ネギの当たり判定が狭い固定座標に依存 | 表示位置と判定位置が別管理 | 0（判定拡大）、1（表示と判定を同一データから生成） |
| P5 | 包丁が固定表示で、持っている感覚がない | 道具を直接操作する設計になっていない | 1 |
| P6 | 調理よりCanvas外のUI操作が中心になっている | 工程ボタン・移送ボタン・スライダーがCanvas外 | 1 |
| P7 | 食材が場所を移動している実感が乏しい | 独立した3シーンの切り替え | 1 |

P1〜P4は現行構成のまま直せるため、Phase 1の完成を待たずにPhase 0で解消する。

## 3. 採用するゲーム構成

### 3.1 調理台パノラマ

ゲーム開始から完成まで、一つの連続した3D調理台を使用する。

- 左: まな板、包丁、一本のネギ
- 中央: 未調理の納豆が全量入った鉢、箸、卵、醤油、からし
- 右: ご飯が入ったお茶碗、完成用の木札

まな板の上は「納豆置き場」と「ネギ置き場」を重ならない2領域に分ける。包丁の切断判定は、刃が通過した領域の食材だけに適用する。

### 3.2 カメラとフォーカス

カメラ位置は画面表示の状態であり、GameStateには含めない（§7）。カメラは調理台に沿った水平位置`cameraX`を連続値で持ち、次の4つのスナップ位置を定義する。

| スナップ位置 | 構図 |
|---|---|
| `overview` | 3エリア全体。開始時の位置。縦画面では鉢を中央に大きく、まな板とお茶碗を左右端に一部見せる |
| `board` | まな板全体。右端に鉢の一部 |
| `bowl` | 鉢と卵・調味料全体。左右端にまな板とお茶碗の一部 |
| `rice` | お茶碗と鉢の**両方を全体表示**する盛り付け用構図。鉢は画面左寄り、お茶碗は右寄り |

「現在のフォーカス」は、`cameraX`が最も近いスナップ位置に一定距離以内（スナップ間距離の15%）で止まっている場合だけ確定する。パン中、スナップ移動中、どのスナップ位置からも離れている場合はフォーカスなし（`none`）とし、調理操作を受け付けない。

### 3.3 場所の移動

- パンできる面は調理台の天板、壁、空など、§3.4の表で操作対象として定義されていない面だけとする。
- パンを指で離したら、最も近いスナップ位置へ自動で移動する。
- まな板、鉢、お茶碗をタップすると、そのスナップ位置へ移動する（§3.4）。
- 道具または食材を操作している間、および自動移動アニメーション中は、パンとスナップを無効にする。
- **画面左右端から24 CSS px以内で始まったポインター操作は、パンとして扱わない。** Android のジェスチャーナビゲーションや iOS の端スワイプは`touch-action`では止められないため、OSの戻る操作と競合しない領域を空ける。
- `prefers-reduced-motion: reduce`では、スナップ移動をアニメーションなしで即時に切り替える。
- 画面外に「切る・混ぜる・盛る」の移動ボタンは置かない。キーボード用の場所移動は重ねメニューに置く（§5.2）。

### 3.4 操作の割り当て表

ジェスチャーは次のしきい値で判定する。値は実装計画で実機調整してよいが、判定は純粋関数として実装し、ユニットテストで固定する。

- **タップ**: Pointer Downから移動量10 CSS px未満、かつ500ms未満でPointer Up
- **ドラッグ**: 移動量10 CSS px以上。開始時点のヒット対象が操作の所有者になる
- **長押し**: 移動量10 CSS px未満のまま押し続ける操作（醤油・からしのみ）

| フォーカス | 対象 | タップ | ドラッグ / 長押し |
|---|---|---|---|
| `overview` | まな板エリア / 鉢エリア / お茶碗エリア | そのスナップ位置へ移動 | エリア上ではパン扱い |
| `overview` | 個々の道具・食材 | 所属エリアへ移動（調理操作はしない） | パン扱い |
| `board` | 包丁の柄 | — | 包丁を持つ（§4.3） |
| `board` | まな板上の刻んだ納豆 | 鉢へ戻す（§4.5） | — |
| `board` | まな板上の輪切りネギ | 未移送分を鉢へ移す（§4.5） | — |
| `board` | 端に見える鉢 | `bowl`へ移動 | — |
| `bowl` | 鉢の中の納豆 | 「まな板へ」札を表示（§4.2） | — |
| `bowl` | 「まな板へ」札 | 納豆をまな板へ移す | — |
| `bowl` | 箸 | — | 箸を持って混ぜる |
| `bowl` | 卵 | 縁で割る（2回） | — |
| `bowl` | 醤油 / からし | — | 長押しで量を決める |
| `bowl` | 鉢の本体 | 何もしない（箸の誤操作防止） | パン扱い |
| `bowl` | 端に見えるまな板 / お茶碗 | そのスナップ位置へ移動 | — |
| `rice` | 鉢 | — | 鉢を持って盛り付ける（§4.7） |
| `rice` | 木札「いただきます」 | 盛り付け後なら完成（§4.7） | — |
| `rice` | 端に見える他エリア | そのスナップ位置へ移動 | — |
| `none` | すべて | 無視 | パン扱い |

- `overview`では個々の道具を操作できない。360px幅で3エリアを並べると、1エリアあたり約120pxしかなく、§6.2の48px操作領域を確保できないためである。
- 表にない組み合わせは何もしない。
- 「まな板へ」札は、別の場所をタップする、パンする、またはフォーカスが変わると消える。

## 4. コアループ

### 4.1 開始状態

- 納豆は全量が中央の鉢に入っている。
- 鉢の茶色い内容物は、この納豆を表す。
- ネギは未切断の一本としてまな板のネギ置き場に置く。
- ご飯は最初から右のお茶碗に盛られている。
- 卵、醤油、からしは鉢の周囲に置く。
- 納豆を刻まず、そのまま混ぜて粒納豆ルートを進められる。

### 4.2 納豆をまな板へ移す

- `bowl`フォーカス中に鉢の中の納豆をタップすると、鉢の左側に3Dの木札「まな板へ」を表示する。
- 札は、§4.2の移動条件を満たす場合だけ表示する。満たさない場合は、理由を短い日英ステータスで通知する（例: 「調味料を入れた後は、まな板へ移せません」）。
- 札をタップすると、`board`フォーカスへ移動しながら、鉢がまな板の納豆置き場の上へ移動して全量を落とす短い自動アニメーションを再生する。
- 移動条件は次のすべてを満たすこと。
  - 卵・醤油・からしが未投入
  - 混ぜが未開始
  - 盛り付けが未開始
  - **ネギが一切鉢へ入っていない**（鉢を傾けるとネギも一緒に落ちるため）
- 納豆の部分移動は行わない。
- 自動アニメーション中は、ほかの入力をロックする。
- 状態更新はアニメーション完了時に一度だけ行う（§8.3）。

### 4.3 包丁操作

包丁は`board`フォーカス中だけ操作できる。

- **持つ**: 包丁の柄を押すと、3Dの手と包丁が持ち上がり、Pointer Captureを開始する。
- **位置**: ポインター位置からまな板の天板平面へRaycastした点を、包丁の刃の中心とする。指で刃が隠れないよう、刃はポインターの投影点から画面上で48 CSS px上（奥）に表示する。
- **刃の向き**: 刃は常に画面の縦方向（調理台の奥行き方向）に向ける。ネギは画面の横方向に置く。
- **切る動作**: 画面上で下向き（手前向き）のストロークを1回の「切り」とする。
  - 条件: 縦方向の移動が24 CSS px以上、横方向の移動が縦方向の0.6倍以下、ストローク時間が250ms以下
  - ストロークの経路が食材の領域を横切った場合だけ切断を判定する
  - ストローク中は刃が下がる見た目にする（上下の動きは見た目だけで、判定には使わない）
- **離す**: Pointer Upで包丁をまな板上の安全な位置へ戻す。
- **キャンセル**: Pointer CancelまたはLost Pointer Captureでは、途中のストロークを破棄して包丁を安全位置へ戻す。

納豆:

- `whole / coarse / hikiwari / paste`の4段階を維持する。
- 1回の切りストロークが納豆置き場を横切った長さの割合（0〜1）を`passCoverage`として`UPDATE_CUT`に渡す。
- `cutProgress`と`cutStage`はReducerが既存`cut-model`の純粋関数で算出する。Three.js側からは受け取らない。
- 刻みすぎると`paste`になり、ひき割りを超えた失敗として見た目と称号へ反映する。

### 4.4 ネギ操作

**モデル**

- ネギの全長を0〜1に正規化し、先端を0とする。
- 切断位置`cutPositions`（0〜1、重複なし、昇順）を唯一のデータとし、ピースはこの切断位置の区間として決まる。
- 表示用メッシュと当たり判定は、同じピース区間から生成する。事前に分割したパーツは使わず、切断位置で区間を分けて円柱をスケールする。表示位置と判定位置は常に一致する。

**輪切りの定義**

- 幅`SLICE_MAX_WIDTH`（初期値0.08、全長に対する比）以下のピースを「輪切り」とする。
- それより幅の広いピースは、刻まれていない塊としてまな板に残る。鉢へは移せない。
- 例: 中央を1回切っただけでは幅0.5の塊が2つできるだけで、輪切りは0本である。

**派生値**（すべてReducerが`cutPositions`と移送済み区間から算出する）

| 値 | 意味 |
|---|---|
| `cutLength` | 輪切りの幅の合計 |
| `transferredLength` | 鉢へ移した輪切りの幅の合計 |
| `usedAmount` | `transferredLength`と同じ（0〜1）。既存の採点・称号が読む値 |
| `fineness` | 鉢へ移した輪切りの平均幅から算出（細かいほど1） |
| `uniformity` | 鉢へ移した輪切りの幅の変動係数から算出 |

- `fineness`への写像定数は実装計画で決める。その際、既存の理想範囲0.55〜0.8が、実用的な刻み幅（一般的な薄い小口切り）に対応するよう調整する。
- 既存の称号条件はこの単位で次のように解釈される。仕様変更ではなく単位の確認である。
  - ねぎ香る職人: ネギ全長の15〜35%
  - ねぎ山盛り: 65%以上
- ネギ量スライダーは廃止する。

### 4.5 食材を鉢へ戻す

- まな板上の刻んだ納豆をタップすると、包丁の腹で全量を鉢へ戻す自動アニメーションを再生する。
- まな板上の輪切りネギをタップすると、まだ鉢へ入れていない輪切りだけを鉢へ移す。輪切りでない塊はまな板に残る。
- 納豆とネギは別々の3D対象とし、どちらを移すかは食材そのもののタップで指定する。
- ネギは複数回に分けて移せる。移した輪切りは鉢の中にあるため、再切断できない。
- 自動移動中は入力をロックし、完了時に一度だけGameStateを更新する。

### 4.6 鉢での調理

`bowl`フォーカス中だけ操作できる。

- 納豆が鉢にある場合だけ、茶色い納豆表面を表示する。
- 納豆がまな板にあり、ネギも鉢へ入っていない場合は、鉢の内側だけを表示する。
- ネギだけが鉢にある場合は、茶色い面を出さず、鉢底のネギ片だけを表示する。
- 納豆が鉢にない間は、卵・調味料・箸を薄く表示し、操作すると「先に納豆を鉢へ戻してください」と通知する。
- 卵は鉢の縁で2回操作して割る既存ルールを維持する。
- 醤油とからしは、容器を長押ししている時間で量を決める（既存の`amountFromCondimentHold`）。
- 箸をつかむと、手と箸が指へ追従する。鉢内の円運動から混ぜ具合を算出する。
- 糸、泡、卵の混ざり方、色を`mixing`状態へ同期する。

### 4.7 盛り付けと完成

盛り付けは`rice`フォーカス中だけ操作できる。`rice`の構図は鉢とお茶碗の両方を全体表示する（§3.2）。

- 鉢を押すと、手が鉢を持ち上げる。
- 鉢のドラッグ方向、距離、保持時間から傾きと投入量を決める（既存`serve-model`）。
- 盛り付けは何回に分けてもよい。`transferredRatio`は減らない。
- ご飯上の納豆、鉢に残った量、調理台へこぼれた量を同時に表示する。
- 鉢を離しても、自動では採点へ進まない。
- 一度でもご飯へ納豆を移すと、お茶碗の横に置いた3Dの木札「いただきます」が表向きになる。
- 木札をタップすると`FINISH`を適用し、結果画面へ進む。
- 少量盛り、移し残し、大量のこぼれを作った後でも、プレイヤーが任意のタイミングで完成できる。

## 5. 画面とUI

### 5.1 全画面Canvas

- 3D Canvasをゲーム画面全体へ固定する。高さは`100dvh`を基準とし、使えない環境向けに`100svh`、さらに`100vh`のフォールバックを用意する。
- Canvas下に調理ボタン、ステーションタブ、スライダー、完成ボタンを並べない。
- Canvasサイズは`ResizeObserver`、画面回転、Visual Viewportの変更に追従する。
- Safe Areaを考慮し、重要な対象と重ねUIをノッチやブラウザUIの下へ置かない。
- 結果画面と称号一覧は、既存どおりCanvasの上に重ねるパネルとして表示する。

### 5.2 重ねメニュー

Canvas右上に、常時表示の2ボタンを置く。

- ミュート / 音を出す
- メニュー

「メニュー」を開くと、次の項目を持つパネルを表示する。すべてDOMのボタンまたはリンクで、キーボードで到達できる。

- **場所へ移動**: まな板 / 鉢 / お茶碗（キーボード・支援技術向けのスナップ移動）
- **完成**: 盛り付け後だけ有効。木札と同じ`FINISH`を適用する
- 日本語 / English
- 遊び方
- 称号一覧
- 最初からやり直す
- ライセンス（`licenses.html`へのリンク）
- wataryuu.comへ戻る

その他の条件:

- 各ボタンは最低44×44 CSS pxとする。
- 「最初からやり直す」と保存全消去だけは確認ダイアログを維持する。食材移動と完成には確認ダイアログを出さない。
- `prefers-reduced-transparency`では、パネルを不透明寄りにする。

### 5.3 アクセシビリティ

既存仕様§17を維持する。そのうえで本仕様では次を必須とする。

- 3Dの直接操作（切る・混ぜる・盛る）をキーボードだけで完全に再現することは必須としない。
- 場所移動、完成、設定、称号一覧、やり直しは、重ねメニューからキーボードで操作できる。
- 状態の変化（食材の移動完了、操作の拒否理由、完成可能になったこと）は`role="status"`のライブリージョンで日英通知する。
- `prefers-reduced-motion: reduce`では、カメラ移動を即時にし、食材の自動移動アニメーションを150ms以下に短縮する。状態更新のタイミング規則（§8.3）は変えない。

### 5.4 ガイド

初回ガイドは次の内容に更新する。

1. 背景を左右へ動かすか、まな板・鉢・お茶碗をタップして場所を移動する。
2. 包丁や箸をつかんで、切る・混ぜる。鉢の納豆をタップすると、まな板へ移して刻める。刻んだ食材をタップすると鉢へ戻る。
3. お茶碗の前で鉢を傾けて盛り付け、「いただきます」をタップして完成する。

日本語と英語で同じ意味を提供し、完了状態の保存を維持する（§12.3）。

## 6. 3D表現

### 6.1 器

- 鉢とお茶碗は、内面、外面、縁、底を持つ器形状にする（`LatheGeometry`など、厚みのある回転体）。
- 開いた`CylinderGeometry`だけで器を表現しない。
- 鉢とお茶碗は材質と形状を明確に変え、縦画面でも区別できるようにする。
- お茶碗のご飯は器の内側に収め、正面カメラから縁と米の両方が見える高さにする。
- 器は調理台の天板に接地させる。浮いて見えないよう接地影を付ける。

### 6.2 手と道具

- 包丁、箸、鉢を操作している間は、簡略化した3Dの手または手首を道具へ追従させる。
- 手は採点や衝突判定に使わず、操作感を示す見た目とする。
- 包丁の柄、箸、鉢、木札、「まな板へ」札、食材には、個別の当たり判定用プロキシを持たせる。
- 当たり判定用プロキシは表示メッシュより広くする。**操作可能になるフォーカス位置で**、画面に投影したときに最低48 CSS px相当の操作領域を確保する。
- 隣り合うプロキシが重なる場合は、§3.4の表で現在のフォーカスに対して有効な対象だけをRaycastの対象にする。

### 6.3 食材の同期

- 納豆が鉢、まな板、ご飯のどこにあるかを、GameStateから一意に描画する。
- 盛り付け後は、`transferredRatio`に応じて、ご飯上と鉢内の表示量を反比例させる。
- こぼれた表示には、納豆、混ぜ込んだネギ、卵の見た目を反映する。「納豆だけがこぼれる」表現に戻さない。
- 自動移動アニメーションの完了後は、必ずGameStateから再投影して表示を確定する。

## 7. GameState version 2

GameStateはJSON化できる値だけを持ち、Three.jsのオブジェクト、Pointer Event、カメラ位置を含めない。カメラ位置とフォーカスは`CameraRig`が持つ表示状態とする。

```js
{
  version: 2,
  phase: "cooking", // cooking | result
  ingredients: {
    natto: {
      location: "bowl", // bowl | board
      cutStage: "whole", // whole | coarse | hikiwari | paste
      cutProgress: 0
    },
    greenOnion: {
      cutPositions: [],        // 唯一の入力データ。0..1、昇順、重複なし
      transferredPieces: [],   // 鉢へ移した輪切りの区間 [[start, end], ...]
      // 以下はReducerだけが計算する派生値（§4.4）
      cutLength: 0,
      transferredLength: 0,
      usedAmount: 0,
      fineness: 0,
      uniformity: 0
    },
    egg: { added: false },
    soySauceMl: 0,
    mustardG: 0
  },
  mixing: {
    progress: 0,
    circularity: 0,
    speedStability: 0,
    clockwiseRatio: 0,
    aeration: 0
  },
  serving: {
    transferredRatio: 0,
    coverage: 0,
    centerOffset: 1,
    spillRatio: 0
  }
}
```

version 1から次を変更する。

- `station`、`elapsedMs`（未使用）、`natto.amount`（全量移動になり常に1）、`natto.inBowl`、`greenOnion.inBowl`を削除する。
- `natto.location`、`greenOnion.cutPositions`、`greenOnion.transferredPieces`、およびネギの派生値を追加する。
- ネギは未切断部分がまな板に残り、輪切りだけが鉢へ入るため、単一の`location`を持たせない。
- 派生値をstateに保存するのは、既存の`scoring.js`と`achievements.js`を変更せずに使うためである。派生値はイベントから受け取らず、Reducerだけが計算する。

### 7.1 状態イベント

| イベント | ペイロード | 内容 |
|---|---|---|
| `MOVE_NATTO_TO_BOARD` | なし | 納豆をまな板へ |
| `MOVE_NATTO_TO_BOWL` | なし | 納豆を鉢へ |
| `UPDATE_CUT` | `{ ingredient: "natto", passCoverage }` | 納豆の1ストローク分。進み具合と段階はReducerが算出 |
| `UPDATE_CUT` | `{ ingredient: "greenOnion", position }` | ネギの切断位置1つ。派生値はReducerが再計算 |
| `TRANSFER_GREEN_ONION` | なし | 未移送の輪切りをすべて鉢へ |
| `ADD_EGG` | なし | |
| `ADD_CONDIMENT` | `{ condiment, amount }` | |
| `UPDATE_MIX` | `{ ...metrics }` | |
| `UPDATE_SERVE` | `{ ...metrics }` | 最初の盛り付けもこのイベントで受け付ける（旧`TRANSFER_TO_RICE`は廃止） |
| `FINISH` | なし | |
| `RESET_RUN` | なし | |

- 旧`SWITCH_STATION`と旧`TRANSFER_TO_BOWL`は廃止する。
- 移動系イベントはペイロードを持たず、§7.2の条件を満たさなければ拒否される。そのため、同じイベントが二重に届いても状態は二重に変わらない。

### 7.2 不変条件

- 納豆の`location`は`bowl`または`board`のどちらか一方である。
- `MOVE_NATTO_TO_BOARD`は、次のすべてを満たす場合だけ受け付ける。
  - 納豆が鉢にある
  - 卵・醤油・からしが未投入
  - `mixing.progress === 0`
  - 盛り付けが未開始
  - `greenOnion.transferredLength === 0`
- `MOVE_NATTO_TO_BOWL`は、納豆がまな板にある場合だけ受け付ける。
- 納豆の切断更新は、納豆がまな板にある場合だけ受け付ける。
- ネギの切断位置は、移送済みの区間の内側にあるものを拒否する。0以下、1以上、既存の位置と同じ値も拒否する。
- `TRANSFER_GREEN_ONION`は、未移送の輪切りが1つ以上ある場合だけ受け付ける。
- `transferredLength`は`cutLength`を超えず、減らない。
- 卵、調味料、混ぜ、盛り付けは、納豆が鉢にある場合だけ受け付ける。
- ご飯へ一度でも盛った後は、切断、食材移動、卵、調味料、混ぜを受け付けない。
- `serving.transferredRatio`は減らない。
- `FINISH`は`serving.transferredRatio > 0`の場合だけ受け付ける。

## 8. ソフトウェア構成

### 8.1 KitchenWorld

既存の`cut-station.js`、`mix-station.js`、`serve-station.js`を、同時に表示するワールド部品へ再編する。

| 部品 | 担当 |
|---|---|
| `BoardArea` | まな板、包丁、納豆、ネギ、切断表示 |
| `BowlArea` | 鉢、箸、卵、調味料、混ぜ表示、「まな板へ」札 |
| `RiceArea` | お茶碗、ご飯、盛り付け、こぼれ、木札 |
| `CameraRig` | `cameraX`、パン、スナップ、フォーカス判定、画面回転への対応 |
| `InteractionController` | §3.4の表に基づくRaycast対象の選択、ジェスチャー判定、Pointer Capture、操作の所有権、キャンセル |
| `TransferAnimator` | 納豆を出す、納豆を戻す、ネギを移す短いアニメーション |

各部品は`renderState(state)`で表示を作り直せるようにし、context recovery時に途中のThree.js状態へ依存しない。

### 8.2 純粋ロジック

- 次は、Three.jsから分離した純粋関数とする。
  - 切断、混ぜ、盛り付け、採点、称号判定（既存を維持）
  - ネギのピース・派生値の算出
  - ジェスチャー判定（タップ・ドラッグ・長押し・切りストローク・端からの操作の除外）
  - フォーカス判定（`cameraX`からのスナップ位置判定）
- 状態遷移はReducerだけが行う。
- Three.js側はイベント候補を生成する。Reducerが拒否した場合は、表示を確定変更しない。
- 既存の20称号IDと保存キーは維持する。

### 8.3 自動アニメーションと状態更新

- 自動アニメーションは開始時に`TransferAnimator`の世代番号を受け取り、完了時に世代番号が一致する場合だけ対応イベントを一度dispatchする。
- `RESET_RUN`、context loss、KitchenWorldの再構築では世代番号を進める。中断されたアニメーションは、イベントを出さずに破棄される。
- 状態は完了時にだけ変わるため、中断時に状態を巻き戻す処理は不要である。表示はGameStateから再投影する。

## 9. Android Chrome対応

- 対象は、実装時点の最新2メジャー相当のAndroid Chromeとする。
- 縦画面360×800前後を主要な受け入れサイズとする。
- Androidでは初期DPR上限を1.5とする。
- 低性能端末でも、入力判定は描画品質から独立させる。
- Pointer Down後に対象が確定した場合だけPointer Captureする。
- 次の場合は、操作の所有権を必ず解放する。
  - `pointercancel`、`lostpointercapture`
  - 画面回転
  - `visibilitychange`でタブがバックグラウンドへ移ったとき
- ゲーム領域にだけ`touch-action: none`と`overscroll-behavior: none`を設定し、ページのスクロールやプル・トゥ・リフレッシュと競合させない。OSの戻るジェスチャーは§3.3の端の除外で回避する。
- **品質の自動低下**:
  - 直近2秒のフレーム時間の平均が33.3msを超えたら、品質を1段下げる。
  - 下げる順は、糸 → 泡 → 影 → DPR（1.0まで）とする。
  - 1段下げた後は、次の判定まで2秒待つ。
  - 同じセッション内では品質を自動で戻さない（上下を繰り返さないため）。

## 10. エラー処理と復旧

- WebGLの初期化に失敗した場合は、Canvas内に日英の説明と再読み込み操作を表示する。
- Context lossが起きたら入力を止め、確定済みのGameStateを保持する。自動アニメーションは§8.3の世代番号で無効化する。
- Context restored後は、KitchenWorld全体を破棄して作り直し、GameStateから3エリアを再投影する。カメラは直前のスナップ位置に戻す。
- Audio失敗とlocalStorage失敗は、既存の無音・メモリ保存のフォールバックを維持する。
- 不正な操作順はReducerで拒否し、必要な場合だけ短い日英ステータスを通知する（§4.2、§4.6）。

## 11. テストと受け入れ条件

### 11.1 状態遷移（ユニットテスト）

- 初期状態で、納豆は鉢、ネギはまな板、ご飯はお茶碗にある。
- 粒納豆のまま、混ぜ、盛り付け、完成できる。
- 納豆を全量まな板へ移し、`coarse / hikiwari / paste`へ刻み分け、全量を鉢へ戻せる。
- ネギだけを刻んで鉢へ加え、納豆は粒のまま維持できる。

- 中央を1回切っただけのネギは、使用量0のままである。
- ネギを鉢へ入れた後は、納豆をまな板へ移せない。

- 移送済みの区間への切断を拒否する。
- 盛り付け前は`FINISH`を拒否し、盛り付け後は任意の量で完成できる。
- 移動系イベントを2回続けて適用しても、状態は1回分しか変わらない。
- 20称号それぞれについて、代表状態から到達できる（既存fixtureをversion 2へ更新する）。

### 11.2 入力（ユニットテスト）

- §3.4のタップ・ドラッグ・長押しのしきい値判定
- 切りストロークの判定（縦方向の距離、横方向との比率、時間）

### 11.3 表示（実ブラウザ）

- 納豆が鉢にある場合だけ、茶色い納豆表面を表示する。
- 納豆がまな板にある間、同じ納豆を鉢へ二重に表示しない。
- ネギだけが鉢にある場合、鉢を茶色くしない。
- ご飯、お茶碗、鉢の縁、内面、底が、各スナップ位置で欠けずに見え、器が天板に接地している。
- 盛り付け量に応じて、ご飯上の量が増え、鉢内の残量が減る。
- こぼれた表示に、納豆以外の投入済み具材も反映する。
- ネギの画面上の位置と切断位置が一致する。

### 11.4 入力（実ブラウザ）

- 包丁、箸、鉢、木札の操作領域が、操作可能なフォーカス位置で48 CSS px以上ある。
- 包丁の操作中にパンが起きない。
- パン中に道具を誤って持たない。
- Pointer Cancel後に道具が指へ張り付かず、次の操作を始められる。
- 自動移動を連打しても、イベントが重複しない。
- Android実機で、画面端からのスワイプがOSの戻る操作として動き、ゲームのパンにならない。

### 11.5 対応環境

- Android Chromeの360×800前後で、Canvasが表示開始から0pxへ縮まない。URLバーの表示・非表示が切り替わってもCanvasが追従する。
- 縦画面と横画面で、まな板、鉢、お茶碗へ到達できる。
- Android Chrome、iOS Safari、デスクトップのChrome、Safari、Edgeで、主要ルートを最後まで遊べる。
- 性能は次の2つで確認する。
  - Chrome DevToolsでCPUを4倍に減速し、360×800・DPR 3を模擬した状態で、品質の自動低下後に平均30fps以上
  - Android実機（使用した機種名を実装計画と検証記録に残す）で主要ルートを最後まで遊べる
- PCでは60fpsを目標とする。
- キーボードだけで、メニューからの場所移動、完成、設定、称号一覧、やり直しができる。
- 日本語と英語で、ガイド、通知、設定、結果、称号の意味が一致する。

## 13. 今回の確定事項

- B案「調理台パノラマ」を採用する。
- Phase 0（現行構成での緊急修正）を先に公開し、その後Phase 1でパノラマへ移行する。
- 開始時は、鉢に未調理の納豆が全量入っている。
- 納豆をまな板へ移す場合は全量移動とし、部分移動しない。ネギを鉢へ入れた後は移せない。
- 開始カメラは鉢中心の全景とする。全景では場所移動だけを受け付ける。

- ネギ量は、輪切りにして鉢へ移した長さで決める。幅の広い塊は使用量に含めない。
- 完成は、3D木札「いただきます」のタップ、または重ねメニューの「完成」で確定する。
- 画面構成は、全画面Canvasと重ねメニューにする。
- 保存データの`version`は1のまま、真偽値の設定を追加して新しいチュートリアルを管理する。
